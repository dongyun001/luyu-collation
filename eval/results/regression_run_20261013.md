## 这次实测能说什么

1. **链路正常、五类都能出**：五类校勘点各有 1 处由人工注入/选定的 ground truth，真实模型全部检出且类型判对，
   异文那条还给出了别本依据（`豫章故郡` / `南昌故郡`）。
2. **干净通行本文本上零误报**：4 段干净对照（《史记》《孟子》《荀子》《韩非子》选段）全部 0 条建议。
3. **输出契约可靠性**：9 段 `droppedCount` 合计 0，没有一条模型输出因不合契约被丢弃。
4. **耗时**：单段 4.6–26.8 秒，可用于给演示/录屏估时。
5. **规则只改置信度、不改检出集合**（设计如此）：两组条目集合一模一样。

## 三条必须与上面的数字一起读的边界

1. **这不是准确率。** 用例集自己的 README 写明：回归集"只作 Prompt 回归输入，不作校勘底本，
   **不参与任何对外的准确率宣称**；对外的指标一律以 `docs/EVAL.md` 定义的评测集为准"。
   而且 N=9（其中校勘点仅 5 处），"5 处全中"在统计上没有推论力，干净文本也是短句。
   材料里若要引用，只能写成"回归集 9/9 未发现退化 + 误报观察 0/4"，**不能写成检出率或准确率**。
2. **两次独立跑无法分离消融开关的效果——这是本次暴露的方法学问题。**
   模型自身的置信度在两次运行之间就有波动：异文那条毫无规则介入（异文不在任何字表里），
   却从 0.75 变成 0.72；而讹字/通假本应 +0.1（`server/services/confidence.py` 的
   `CONFIDENCE_BOOST`，仅对命中形近/通假字表的条目生效），却被波动掩盖成 +0.05。
   想干净地量化开关效果，必须在**同一次模型输出**上跑两条后处理路径——
   这正是 `server/tests/test_collate_pipeline.py::test_ablation_switch_skips_rule_confidence_boost`
   做的事（同一条目：开关开 1.0 / 关 0.95）。**结论：消融的因果证据用单测，真实模型上的两次独立跑只能当旁证。**
3. **要出对外指标，仍缺三样**（`docs/EVAL.md §2`）：200–500 字的选段（≥10 段）、
   五类各 ≥10 点且总量 ≥60 点（其中**异文的别本依据必须人工给出**）、两人复核 20%。
   工具已就绪（`eval/mark_to_labels.py` 自动算索引、`eval/self_check.py` 拦配额与区间错位、
   `eval/run_compare.py` 跑批并自动记录 Prompt 版本与开关、`eval/judge.py` + `eval/report.py` 出表出图）。
